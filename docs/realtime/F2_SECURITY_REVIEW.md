# F2 security design review

Reviewed on 24 November 2026. The baseline findings below describe the legacy packet path. The current opt-in Flow wire profile and its verification scope are recorded under [Implemented F2 profile](#implemented-f2-profile).

## Link-level identity

1. A dialer compares with an expected Peer ID from a pinned contact, verified invite or existing authenticated relationship. Discovery endpoints and relay claims are hints. Inbound policy must say whether to accept any proven key or require a named identity. Proof of key possession grants no relay, application or resource rights. First-use identity decisions belong to application policy.
2. Keep legacy transport interoperability. New QUIC Flow links require completed TLS 1.3 and a mutually signed fresh exchange. Verify TLS certificate proof of possession for the F2 path and independently bind LP2LN identity using Quinn's exporter with a dedicated label. Bind ordered roles, both Peer IDs and fresh challenges, complete offers and selected version/suite/capabilities, ALPN and exporter label/context. Authenticate the two roles in distinct signature domains over a canonical, length-delimited transcript with independent vectors. Publish readiness after both proofs and role outcomes are validated. A MITM terminating two QUIC connections obtains different exporters and cannot reuse either connection's proofs on the other.
3. Disable 0-RTT FlowOpen, data and relay admission. TLS resumption conveys no Flow authority by itself. Use a strict handshake size bound, deadline, pending listener and node-wide caps, IP-prefix accounting where applicable and a bounded crypto worker budget. Require address validation for publicly exposed challenged endpoints under load. Allocate retained per-peer state after identity and admission. Authenticate both sides on every new link even when the Flow remains open.
4. Sign complete ordered capability offers so a relay or attacker cannot strip features before commitment. A failed F2 negotiation or signature is a terminal F2 result. Legacy fallback is an explicit application decision and can never lower an existing Flow's requirements. A mixed peer can continue existing V3/V4 traffic without a Flow context.

## Endpoint E2E context

- Evaluate the official `Noise_XX_25519_ChaChaPoly_SHA256` pattern with a maintained pinned `snow` release and published vectors. Use its ephemeral X25519 exchange, cipher and transcript functions. Each endpoint verifies a signed, versioned certification of the remote Noise static key against the handshaken key and expected LP2LN Peer ID. Bind endpoint roles, protocol offers, session purpose and canonical endpoint session identifiers. The E2E transcript is independent of each hop's TLS exporter and IP address. Explicit endpoint confirmation precedes application traffic.
- Keep directional keys from the library's Split. For M1, shared endpoint-session keys require a single nonce allocator per direction and epoch across all flows. Include `FlowID`, direction, record type, nonce, session ID and epoch in the protected record and check repeated outer fields. Independent per-flow key domains need independent Noise contexts or a reviewed interoperable library key schedule. Burn nonces after encryption even if admission is cancelled. Reject counter exhaustion. Retransmit exact ciphertext or re-encrypt with a fresh nonce and separately deduplicate application message IDs.
- Verify AEAD before committing replay state. The bounded window accepts unseen reordering and rejects duplicates and values older than its floor. Bad AEAD, invalid protected/outer comparison or wrong-epoch input never advances it. Simultaneous copies on two links share the replay mark. Select the epoch using bounded known-state lookup before allocating. Mutable routing information remains visible to authorized relays and independent of the authenticated E2E record.
- Start a fresh authenticated Noise handshake for rekey and link its transcript to the existing endpoint session using an authenticated transition on the old context. Confirm both endpoints before switching send epochs. Permit a bounded two-epoch receive overlap with independent replay windows, a fixed retirement deadline and no fallback when late control arrives. A process restart uses fresh keys and IDs. Redact keys, plaintext and secrets from logs, audit copies and library zeroization and drop pending, active and retiring state on shutdown. Forward secrecy applies to recorded completed sessions assuming fresh ephemeral keys are destroyed. It does not cover an endpoint compromised during the session.
- A new path is a separately authenticated link plus an E2E challenge/answer bound to the active endpoint session and proposed path association. A relay forwards opaque endpoint handshake/records while authenticating and limiting each adjacent hop. Failure or IP change must never reset a Flow sequence, replay window or origin authorization. Keep endpoint handles and Flow IDs above Path and Link. Exercise simulated path swap during F2 before implementing production handoff.

## Required vectors and negative tests

| Vector | Required observation |
|---|---|
| Expected identity, distinct sender/receiver roles and published Noise XX vectors | Both independent endpoints agree on transcript, identities, suite and confirmation. A swapped role, wrong Peer ID, expired certificate or altered Noise static-key binding fails before readiness. |
| Same valid proof with a second TLS exporter, truncated capabilities, substituted ALPN, timeout or legacy protocol response | The peer stays unverified and no Flow state or implicit downgrade results. |
| Wrong key, one-bit ciphertext corruption, modified outer Flow ID / epoch / version / direction | No payload, epoch advance or replay mark. A valid subsequent record at the same sequence is accepted. |
| Duplicate, valid reorder, stale packet outside the window, far-future unauthenticated value, two concurrent copies | At most one authenticated application delivery. Valid reorder is accepted within the window and unauthenticated values cannot evict legitimate records. |
| Interleave two flows and directions, retry after writer cancellation, hit counter limit | Nonce uniqueness under every key. Cancellation and exhaustion have explicit outcomes. |
| Confirm/reject rekey, overlap/retirement, restart, simultaneous rekey, path switch | Valid old/new records are accepted only in the defined overlap. Retired keys cannot be reactivated. A path switch preserves Flow identity and replay state. |
| Relay captures, tampers, duplicates or redirects signaling/records | No relay plaintext, substituted endpoint proof, altered delivery or privilege grant. The relay can observe envelope size, routing and timing. |
| Saturate pre-auth queue, oversize/truncated record, pending handshake cancellation, shutdown and expired epoch | Bounded tasks, held bytes and crypto state. No retained keys after teardown. |

F2 requires pinned reference vectors and separate interoperability and security review. No F2 security tests have been executed against production code during this stage. The F0/F1 strict V3/V4 and replay tests exercise legacy behavior.

## Updated F1 observations

The node now accounts for native session frame allocations from length prefix through decode and dispatch, plus chunk reassembly and compatibility fanout. Native socket and library buffering remain separately bounded. Caller-owned legacy allocations and application-owned retained messages are explicit boundaries. Wire candidates cannot claim priority before authentication. An authenticated control admission point remains needed.

The two-link QUIC test exercises an authenticated legacy sender across independent active connections. A previously unseen sequence at distance 129 is rejected once a new path advances the shared origin window. An unseen sequence one position behind is accepted. These outcomes preserve the existing replay width. A receiving process retains no persistent legacy replay map across restart. The sender's durable sequence reservation addresses a different property. Fresh endpoint session IDs and keys at F2 restart must reject old-context data.

## Implemented F2 profile

- QUIC Flow has a distinct opt-in ALPN. The Flow-only rustls verifier verifies TLS 1.3 CertificateVerify proof of possession. An arbitrary self-signed certificate is acceptable only as a TLS carrier. Both LP2LN identities sign role-separated transcripts over the exact exported channel keying material, the two nonces, both expected identities, full ordered offers, protocol and FlowID. Inbound policy must explicitly authorize the claimed PeerID/protocol pair, then successful proof is required before allocating an active peer slot.
- A separate Snow 0.10.0 Noise XX exchange uses the X25519, ChaChaPoly and SHA-256 suite. The K256 peer identity certifies the local Noise static key for the specific roles, FlowID, protocol and epoch. Delegation expires. New Noise handshake keys are generated separately from the LP2LN identity and TLS keys. The prologue excludes TLS exporter data, path and address. An authenticated challenge/confirmation and clock-bound exchange gates application delivery.
- The two Noise Split directions are distinct. Within each direction, datagram and ordered control counters occupy disjoint even and odd nonce domains. Each lane has its own replay window. Protected headers repeat version, FlowID, epoch, nonce, kind, sender role and deadline. Verification precedes replay commit. The midpoint nonce limit is 2^32 records per lane per epoch. Live rotation uses the old authenticated control lane to authorize a fresh Noise handshake, then confirms the new keys. A previous epoch has a two-second receive-only overlap and an independent replay window. Restart generates a fresh FlowID and fresh keys. The F1 legacy replay gap after receiver restart remains isolated from Flow.
- Each transport allows at most 32 pending/active Flows and the node permits four authenticated Flows per peer. The inbound allowlist and accept queue are bounded. Pre-auth, native, control and data bytes have distinct limits. Cancellation and shutdown cancel operations, drain Core queues and drop active/retired key objects. Owned Noise private input and clear record scratch are explicitly zeroized. This does not claim that allocator, compiler or every internal Snow primitive performs forensic zeroization.
- Tests use Cacophony's independent Noise XX reference bytes, incorrect link exporter, role and peer substitutions, version/capability downgrade, Noise cert binding and expiry, corrupted ciphertext, wrong session keys, reflection, reordered and duplicate datagrams, control under a newer data sequence, epoch overlap, retirement and rollback. On real QUIC, wrong expected peer, unauthorized protocol and legacy-only ALPN all fail without Flow delivery. No live relay or independent implementation interoperation was exercised. The scope is a local preview.
