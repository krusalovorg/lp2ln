# Real-Time Architecture

The compatibility baseline is Core `65925aaf`, the Android git dependency. The legacy `Packet` postcard layout, existing protocol IDs and app entry points define the wire that interoperating deployments already use.

## Current ingress and egress

- TCP, UDP and QUIC readers decode one transport frame. The transport ingress channel has a configurable item count. The Router processor queue admits pending work by estimated retained bytes and item count. Small, untagged traffic can use reserved room. This classification also covers encrypted legacy control whose type is only available after decryption.
- Pending data is limited to 1,024 jobs or the configured ingress count if lower and 65 MiB estimated bytes. The reserved lane allows 32 jobs and 128 KiB. Up to eight reserved jobs can be selected before a data job. Queue admission drop counts and replay/late rejection counts and queue wait sample counts, totals and maxima are available from `Router::ingress_metrics()`. Already running workers, broadcast queues and the upstream legacy transport channel are outside this byte budget.
- Each built-in writer retains up to 1,024 queued frames with a byte budget of 16 MiB for TCP/QUIC and 8 MiB for UDP. Byte permits stay attached to frames through writing. Producer futures awaiting admission still own their input buffers. This is a per-session writer limit.
- A UDP listener is the receive owner. It keys a bounded map by source tuple and hands the triggering datagram and later data to per-session inboxes. Each inbox can hold 64 datagrams and the listener shares an 8 MiB estimated datagram budget across all peers. Dial and punch sockets use their own reader and filter on the configured peer tuple. The data demultiplexer and NAT traversal socket lifecycle are separate.
- A locally originated packet may acquire a request ID. A forwarded packet retains its original ID, signed fields and ciphertext. The Registry's adjacent peer is separate from the signed author. Relay duplicate suppression runs in the default processor after its signature policy and adjacent-peer checks. Local envelope processing checks authenticity, decrypts and rejects replay before publication. Legacy and secure broadcast receivers share one immutable message allocation.
- Legacy chunk assembly is limited by the existing per-stream and per-session rules plus an aggregate 128 MiB memory charge. It moves chunk buffers into the assembly map and merges after releasing the assembly lock. The legacy dispatcher assembles before signature checks. This placement and signed chunk behavior are documented in [Security](SECURITY.md).

## Delivery measurements

| Stage | Observation |
|---|---|
| Sender transport admission | Session accepts encoded bytes to its local writer queue. Legacy send/byte metrics are queue admission counters. |
| Decoded ingress | Router received a decoded transport packet. May include malformed LP2LN identity, replays or packets later counted as rejected. |
| Authenticated ingress | Default processor required and validated the signature, matched the available adjacent-peer binding and checked the envelope where applicable. |
| Authenticated local processing | Authenticated packets addressed locally were accepted by the processor. A subscription may independently lag. |
| Confirmed application observation | Benchmark sink validates sender, receiver, expected request ID, protocol and payload and counts every ID once. Application-level ACKs define delivery where the app's contract requires a remote confirmation. |

## Next layer

The [F2/M1 specification](F2_M1_SPEC.md) adds an optional transport-neutral Flow layer over existing links. A logical Flow binds to an authenticated peer and holds its delivery contract when a path changes. Realtime carries expiring datagrams. Reliable control uses a separate lane. A consumer such as RTC, VPN, game or messaging chooses a policy through the same embedded API.

## F1 follow-up limits and failure semantics

| Location | Current bound | Limitations |
|---|---|---|
| TCP/QUIC frame reader and writer | 10 MiB wire frame. 1,024 queued frames and 16 MiB retained writer capacity per session. A held write remains charged until completion or cancellation. | Decoder and framing may temporarily retain both wire and decoded memory. HTTP-obfuscated framing also has a 10 MiB body cap. A reader holding a decoded frame is outside the writer budget. |
| UDP listener and writer | 1,024 endpoint entries, at most 64 items per endpoint inbox, aggregate 8 MiB per listener. Dedicated readers hold one datagram buffer. UDP writers use 1,024 items / 8 MiB per session and enforce 65,507 B wire maximum. | Kernel socket buffers and dedicated sessions are outside the listener semaphore. UDP can lose datagrams at socket or queue admission under overload. |
| Quinn transport | 16 MiB QUIC connection receive credit, 1,250,000 B default per-stream receive credit and 10,000,000 B send window. Legacy plain QUIC disables DATAGRAM and incoming unidirectional streams. Optional HTTP/3 keeps existing uni-stream and DATAGRAM settings. Pending incoming connection buffering is 128 entries, 256 KiB per entry, 8 MiB aggregate. | Flow-control credit does not describe heap overhead. Retransmission metadata, kernel socket queues, concurrent connections and unconsumed streams require a node-wide policy. |
| TCP/QUIC listeners | 64 tracked pending tasks each. TCP holds extra connections in the kernel backlog. QUIC refuses additional attempts. TCP hello, first QUIC stream, and session-channel handoff are time-bounded. Stop cancels and joins listener tasks. | Sessions posted to the registry and long-lived accepted connection state have separate lifetimes. HTTP/3 connections consume one pending slot while served. |
| Legacy transport-to-Router channel | 16,384 elements by default. TCP/QUIC enforce 10 MiB wire frames. | Nominal theoretical wire payload across the default slots is 160 GiB. This count cap is not a useful shared heap bound. IncomingPacket can also come from public/caller-supplied senders. |
| Router pending processing | 65 MiB / up to 1,024 regular jobs plus 128 KiB / 32 reserved jobs. Reliable ingress waits up to 2 s for capacity except within the shutdown deadline. At admission failure it logs, increments a counter and closes the link. UDP overload remains a counted discard. | Active processor jobs and one waiting Router job are outside the queue gauges. A slow external processor can stall other links for the admission interval. |
| Legacy local fanout | Each raw and authenticated broadcast ring has 4,096 slots by default. Local decrypted payload may reuse an Arc across the rings. Tokio exposes RecvError::Lagged to each slow consumer. | No byte cap or network acknowledgement. A consumer can keep an Arc beyond the ring or discard Lagged. A ring of 4,096 maximal 64 MiB legacy reassemblies would be 256 GiB of payload before aliasing or other bounds. |
| Chunk assembly and control state | 128 MiB aggregate incomplete chunks, 64 MiB per stream with default configuration. Incoming-session and event queues are item-bounded. | Merged buffers and temporaries have separate ownership. Legacy fragments are buffered before packet authentication, and incomplete streams can retain a charge up to expiry. |
| File log queue | 1,024 records of up to 4 KiB, one worker thread for the process. | Extra queue records are counted and dropped. Console messages are separate. |

There is no defensible single node-wide byte total obtained by adding these numbers. Some limits apply per link and some ownership overlaps. A bounded ingress handle needs to hold a byte permit through decode, processing and bounded application handoff. Preserve legacy entry points with an adapter and report payload references held by application code separately. Admission success confirms a local send offer. Transport failure, ingress refusal, subscriber lag and protocol delivery acknowledgements are distinct observations. Local WriterAdmissionError::FrameTooLarge leaves a healthy session open. Closed signals transport-side admission failure. Chat and file handlers need their own acknowledgement to confirm remote handling.

Sequencing and enqueue for locally encrypted legacy packets are serialized by 64 recipient-hashed gates. This fixes concurrent sender reordering before a reliable writer admits the frame. It preserves legacy wire bytes and replay checks. Simultaneous routes and receiver processing can still reorder past the legacy window and do not imply authenticated reliable Flow delivery.

## Prior node-wide ingress accounting checkpoint

Native TCP, QUIC and UDP session readers use the same node ledger. TCP and QUIC reserve bytes after the frame length and before allocating the body. The ledger conservatively accounts for the simultaneous serialized and owned representations. The codec preflights the postcard hop count before allocating the hop vector. During subsequent queueing the permit reflects the actual owned capacities plus room for the legacy AEAD plaintext, when applicable. HTTP-mimic headers hold a separate bounded reservation and release it before the body reservation. TCP's pre-registration signed hello uses a 64 KiB body limit and the existing per-listener pending-hello ceiling.

| Scope | Candidate limit | Accounting |
|---|---:|---|
| Managed ingress | 256 MiB/node | Frame reservation, weighted transport-to-Router channel, dispatcher jobs, active workers and originating chunk buffers. |
| Ingress session | 144 MiB/session | Sums every live reservation associated with the local session ID. |
| Ingress adjacent peer | 160 MiB/known peer | Sums reservations across already bound sessions. Before binding, global and session limits apply. The scope follows the session registry. The permissive legacy mode can populate the registry without a signature, so the global and per-session ceilings still apply. |
| Fanout and IPC | 128 MiB/node | Legacy ring allocation and App Plane copies, IPC encode/decode reservations, queued encoded frames and active IPC writes. |
| App Plane | 48 MiB/subscriber or IPC connection | Subscriber events and IPC socket work have separate owners, with the shared node fanout cap applying to both. |
| Reassembly | 128 MiB retained chunks and the configured per-stream limit | Chunk data brings its existing permit. The additional output allocation must fit immediately before merging. Expiry runs even on an idle Router. |

The ingress ledger checks nested scopes together. Reliable readers wait with a deadline before allocating and close when a reservation or handoff fails. They never hold a partial scope while waiting for a second scope. UDP refusal is best effort. Chunk merging and fanout request their additional reservation without waiting. Shutdown drains or releases pending reservations, including full legacy rings. Public Session and Router entry points retain additive adapters for older providers. A custom provider that supplies a preallocated IncomingPacket through the raw mpsc sender starts accounting when Router receives it. Sender-owned memory before that point is outside the managed queue.

Legacy broadcast continues using Tokio's existing receiver type. Each frame shared between both rings has one charge while either ring holds it. A periodic reap and publish-time reap release charges once the bytes have moved to consumers. App Plane compatibility mpsc receivers use the same ownership boundary. IPC moves encoded queues under the shared ledger. An external application's Arc or owned message is beyond core accounting after it receives the message. Closing the Core rings releases Core ownership, including when legacy receiver handles outlive the Router.

Legacy fanout is best effort. Slot eviction produces Tokio Lagged, and byte refusal is counted separately because a refused record never became a ring slot. Reliable writer admission and ingress acceptance do not promise that a legacy subscriber observed the record. Protocol ACKs remain authoritative where defined. A future Reliable Flow needs a typed subscriber handle, session-level delivery outcome and explicit admission/drop reporting.

The ledger does not directly meter OS socket queues, Quinn's internal connection/stream allocations, the UDP listener's bounded wire inboxes or preallocated frames supplied by third-party legacy transports. Quinn receive credit and the UDP inbox budget still provide independent bounds. Unauthenticated wire hints cannot consume the former heuristic reserved worker lane. Authenticated control scheduling still needs an admission point after identity and before data competition, with bounded peer eligibility and no reordering across the same replay domain.

Legacy egress orders sequence assignment and writer admission by exact recipient. Dispatch keeps one in-flight authentication/replay check per input session. This guard can release before asynchronous application work or forwarding. An unrelated session remains eligible while one reader authenticates, and one recipient waiting on its writer cannot hold an unrelated recipient's gate. A different input link can still deliver an earlier legacy frame after the author's shared replay horizon has advanced.

## F1 completion scope and direct Realtime Flow

The native UDP listener now shares the managed ingress ledger. Its reusable receive buffer and queued datagram allocations carry node-wide reservations alongside the existing 8 MiB per-listener ceiling. Inbox ownership remains charged through decoding. The first datagram's validation uses a separate pre-auth reservation. The plain UDP decoder reads directly from the wire slice. Managed TCP hello allocations and QUIC pending handshakes use a 16 MiB pre-auth pool. Application decode reserves wire/owned overlap and the worst simultaneous legacy signature or AEAD temporary. Legacy packet metadata and crypto cache/state tables have finite limits. Replay entries are never evicted to admit another origin. New origins encounter explicit refusal at the cap.

Managed QUIC connections reserve native **receive credit**, not a heap measurement. The node caps the aggregate credit at 256 MiB, including 8 MiB reserved for a listening endpoint's pending input, 4 MiB stream receive credit per connection and the associated configured native buffer allowances. Credits follow pending connection, live session or Flow and are released on teardown. Proprietary provider internals, OS socket memory, caller-owned buffers and frames already handed to external application code are outside this accounting contract. The previous per-component discussion describes the original baseline.

A 2 MiB verified-control pool includes a 256 KiB cap per adjacent peer. Legacy control reaches it only after strict signature, applicable AEAD/replay checks and semantic control decode. The same pool funds authenticated Flow rekey scratch. Legacy control still travels on the shared legacy stream and inherits its transport-level head of line. Flow control has a dedicated ordered QUIC stream, byte-sized frames, completion deadlines and a distinct nonce lane.

Legacy authentication executes concurrently for at most eight outstanding jobs per input link and remains globally capped by the existing dispatcher workers. Per-link arrival tickets commit signature/AEAD outcomes and replay mutations in receive order. Invalid and cancelled tickets cannot advance past a preceding live ticket. Replay remains per signed author across links. A legacy frame over 128 positions behind the author high-water mark still fails, regardless of route.

The direct Flow uses the existing QUIC transport and endpoint with opt-in ALPN. A connection carries one logical Flow, one reliable protocol control stream and bidirectional QUIC DATAGRAMs. It checks the initially authenticated adjacent path and closes on a remote-address change. Flow IDs and Noise keys exclude the local path and hop exporter. Independent verified paths can be added later without changing the cryptographic record namespace.

## Voice preview over the public Flow API

The workspace member lp2ln-rtc is a consumer of Core. Its preview application protocol 0xff82 selects the versioned voice profile. One fresh Flow identifies one invitation. Its random 128-bit FlowID also serves as the v1 CallID. Existing application protocol numbers keep their original behavior. Direct QUIC negotiation, the hop proof, endpoint Noise keys, directional nonces, replay commit and epoch rotation stay in Core.

Flow::control() exposes a bounded ordered request/reply exchange for protocols that opt in. The initiator drives exchanges and the responder supplies its current application message. The existing control task serializes exchanges with rekey. Wire kind 5 uses the existing end-to-end protected control nonce lane. Each side admits one queued command and at most 512 bytes of application data per exchange. A malformed, abandoned or failed exchange closes the control session when processed. Datagrams continue through their independent receive loop. This narrow API intentionally has a single initiator. Future independent reliable streams can negotiate another capability. Flow::recv_with_deadline returns authenticated bytes and the conservative local expiration instant for application-owned buffers.

The RTC signal is a fixed 19-byte frame with version, message kind, required Opus profile and CallID. CallDialog tracks invite, ringing, accept, active, reject, cancel, hangup and terminal acknowledgment. A 30-second monotonic timer bounds ringing. Repeated states are idempotent. No microphone is opened before acceptance. Simultaneous invitations between the selected peers keep the outgoing invitation of the lexicographically smaller Peer ID. Closing the Flow disposes of both codec states. Withdrawing inbound authorization affects future handshakes.

Audio uses one mono channel at 48 kHz. Each capture unit is 960 PCM samples, nominal 24 kbit/s Opus VoIP. Media contains a big-endian 64-bit sequence followed by one Opus packet. Budget is at most 240 encoded bytes and the current path MTU. A 140 ms capture deadline covers ingress and the bounded application jitter buffer. The receiver checks Opus packet duration before insertion and checks expiration again at render. The buffer holds at most seven frames with a two-to-five-frame adaptive prefill, sequence-based reorder, Opus PLC on gaps and rebuffer after three consecutive gaps. There is no in-band FEC in v1. Mouth-to-ear also includes the platform capture and playback pipelines.

Android splits capture, ingress, and playout across three workers. JNI transfers PCM with reusable 960-sample arrays. Capture and decode use separate codec locks. Signaling, audio focus, mute, routing and the foreground-service lifetime remain outside Core. AudioRecord uses VOICE_COMMUNICATION with a single platform AEC/NS chain; device-specific gain processing is left to Android. The preview exports bounded scalar statistics. It does not record the conversation.
